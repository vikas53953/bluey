# Demo evidence in CI without a real key (8 Nov 2026)

Vikas could not test on his PC before the deadline, so the four demos are driven in GitHub Actions instead.

## How it works

- `tools/Boo.QaMockAi` is a Kestrel server that answers like api.openai.com with scripted responses chosen by the
  text of the request (explain / edit / research / focus classification). It generates a self-signed certificate for
  `api.openai.com` at start-up and writes the public half to disk.
- The `demo-ci` workflow (`.github/workflows/demo-ci.yml`) appends `127.0.0.1 api.openai.com` to the runner's hosts
  file and imports that certificate into the runner's `LocalMachine\Root` store. The published Boo.exe therefore
  passes its own official-origin guard (`ProviderEndpoint.IsOfficial`) unchanged. No application code, no provider
  code and no frozen test was edited. The redirect exists only for the lifetime of the runner VM.
- `tests/Boo.Demo.Tests` (FlaUI, xunit, ordered steps, outside Boo.sln) types a fake key into Settings, points the
  file root at a temp copy of `tests/fixtures/native/Boo.QaWorkspace`, then runs: explain with pointer ring, edit ->
  Apply -> Undo, research with source links, Developer Mode focus -> nudge -> Back to it -> happy face. Every step
  saves full-screen PNGs and `.txt` observations.

## Where the evidence lands

- Workflow artifact `demo-evidence`: screenshots, observations, `mock-requests.log` (every request Boo made),
  TRX results.
- Job log step "Contact sheet in the job log": a JPEG contact sheet as base64 between `=====DEMO-SHEET-BEGIN/END=====`
  for reviewers who cannot download artifacts (the usual case from cloud sessions).

## Status

The job is `continue-on-error: true` until it has been seen green, so it cannot turn PR #3 red. Voice (Realtime
WebSocket) is not covered: the mock speaks HTTPS only. Assertions and screenshots prove the UI path; they do not
prove answer quality from a real model.

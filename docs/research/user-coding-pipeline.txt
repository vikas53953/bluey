The software factory idea
A software factory means treating software production like a factory line: work items go in, agents do each step, and automatic quality checks sit between steps. The human role moves from worker to factory designer.
OpenAI's "Harness engineering" post is the clearest real example. Three engineers (later seven) drove Codex to build about a million lines in five months, around 1,500 merged PRs, with no hand-written code. Their summary: "Humans steer. Agents execute."
The harness is everything around the model: tools, docs, linters, tests, review loops.
When an agent fails, the fix is never 'try harder'. Ask what capability is missing and add it.
Taste is encoded as rules and linters, so it applies to every line automatically.
Background agents do 'garbage collection': they scan for bad patterns and open small cleanup PRs.
Factory lesson from Goldratt (quoted in your video)
Every system has one bottleneck. Speeding up anything else does nothing. Fix the bottleneck and it moves somewhere new.
Factory stations, door by door
Idea from Instinct: think of a car factory. Every source describes the same seven stations from a different angle. Raw intent goes in, each station does one job, quality control sits before the exit, and anything that fails loops back.

Three loops and the review/verify/QA loop
Idea from Instinct (Dru Knox, Tessl): a factory runs on three loops. The inner loop is cheap and fast checks while the agent builds. The outer loop is heavy checks once, when the PR opens (agentic QA, mutation testing). The meta loop watches what slipped through and improves the other two.
